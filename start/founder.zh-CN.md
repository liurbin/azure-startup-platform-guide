# Founder 入门与应急卡

[English](founder.md) | [完整中文导航](../README.zh-CN.md)

这张卡只帮助选路和交接，不授权查询或修改账号。链接到的 `draft` 仍只能参考、审阅；不要按草稿操作客户环境。编写时没有访问任何客户订阅。

## 首次使用

先选与你当前状态相符的一行，不必先学完全部 Azure 术语，也不必为了问参考问题提供一套账号 ID。

| 我现在的状态 | 下一步读什么 | 要确认什么 |
|---|---|---|
| 只有 startup 项目资格，还没有 Azure 订阅 | [Credits 与激活](../guides/accounts/credits.md) | 实际项目／offer、当前官方激活入口和准备使用的账号。登录、商业条款接受和支付资料由客户自己处理；不要为了完成清单随意创建付费订阅 |
| 已有订阅，但不清楚 Credits 是否绑定 | [使用前准备](../guides/shared/context-and-tools.md)，再看 [Credits](../guides/accounts/credits.md) | 云环境、账号和真实权益绑定、剩余额度、有效期；看不到的值保持未知 |
| 已经可以调用模型 | [Foundry 访问、审计与费用总览](../guides/models/access-audit-and-cost-controls.md) | 只选当前要解决的访问、日志或费用任务，不重新执行全部入门步骤 |

只需要先认识四个词：**云环境**决定使用哪套 Azure 端点；**租户 tenant**是身份目录；**订阅 subscription**是资源、访问与费用管理的一个范围；**部署 deployment**是具体使用的模型服务部署。不能仅凭团队所在地或语言判断云环境。

正文仍看不懂时，可以让 AI 读取 `AGENTS.md`、`catalog.json` 和所选指南，解释下一步，并把客户实际值留为未知。没有工具不等于必须安装 CLI，更不等于要把账号凭据发给 AI。

这张卡的完成标准是：知道自己处于哪一步、下一项任务是什么、由谁负责。它不代表权益已获批、Credits 已激活或模型已部署成功。

## 异常费用

| 目前知道什么 | 现在该怎么交接 |
|---|---|
| 只是费用上涨，没有泄露证据 | 按[用量与费用核对](../guides/models/usage-and-throttling.md)及[费用指南](../guides/accounts/costs.md)对齐范围、用量时间、币种和刷新情况；不要直接认定 Key 被盗 |
| 已发现 Key 公开，或有可信的持续异常访问证据 | 尽快联系有权限的账号／事件责任人，按独立审核且获批的应急流程决定处置；账单调查可以并行，不等最终发票，也不从草稿中推导操作授权 |
| 自己无法查看账号 | 记录权限缺口，找有权限的责任人或[适用支持渠道](../guides/support/escalation.md)；空白页面不能当作消费为零 |

不要把 Key、token、Authorization header、完整 prompt/response 或发票放进公开 issue、群聊或未经批准的 Agent。不要把同时重置两把 Key、删除资源组或修改生产网络当作通用止损办法。预算告警不是自动停费开关。

## 交接信息

将下面的空白记录复制到获准的私有位置，不要在仓库中填写真实客户信息：

```text
问题和希望得到的结果：
发现时间及所在时区：
已知云环境、服务和资源别名：
已观察到的事实、来源和时间：
尚未证实的猜测：
业务影响、异常调用是否仍持续或未知：
已做动作、执行人角色和时间：
账号或事件责任人、下一联系人：
缺少的权限或证据：
```

没有专职 Cloud Ops 时，由 founder／账号责任人明确谁是获授权的工程师，或走适用的官方支持渠道。权益／计费、技术／安全问题可能需要不同责任人；支持资格也要核实，不能假定每家 startup 都有专属管理员或无限制技术支持。

## 找谁负责

| 问题 | 责任角色 |
|---|---|
| Credits、绑定或费用争议 | 权益／计费责任人；适用的项目或计费支持 |
| Key、访问权限或持续可疑调用 | 获授权的身份／平台或事件责任人 |
| LLM 正文、日志查阅或导出 | 数据／安全责任人 |
